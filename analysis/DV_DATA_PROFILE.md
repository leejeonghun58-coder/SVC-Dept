# DV 3개년 데이터 품질 프로파일

작성일: 2026-09-17  
프로젝트: **서비스 자재 출고·DV 통합분석 시스템**

## 1. 결론

세 파일에는 2023년 4월부터 2026년 3월까지의 DV(Document Volume)가 들어 있다. 고객 코드, 고객명, 장비 일련번호, 월도와 DV 주요 수치는 원본 목록 시트에서 결측 없이 확인되어 분석 기반으로 사용할 수 있다.

다만 현재 상태에서 세 파일을 그대로 이어 붙이면 안 된다.

- `DV(24.04~25.03).xlsx`에 파일명 범위 밖인 `202403` 44,299건이 포함되어 있다. 직전 파일의 같은 달과 공통 업무 필드 35개를 비교한 결과 44,298건(99.998%)이 완전히 같고 양쪽에 1건씩만 차이가 있어, 같은 월의 후속 추출본으로 판정한다.
- `DV(25.04~26.03).xlsx`에는 완전 동일 행 28,473건(5.90%)이 있다.
- `DV(23.04~24.03).xlsx`의 202304~202306 및 202308 행 수는 인접 월의 약 2배다. 완전 동일 행은 아니므로 추출 범위, 계약 이력 또는 장비 상태 행의 중복 여부를 업무적으로 확인해야 한다.
- 연도별 스키마가 40열 → 45열 → 22열로 변했다. 특히 최신 파일에는 CV 세부 열과 REV 세부 열이 없으므로 공통 분석 스키마와 연도별 확장 스키마를 분리해야 한다.

판정: **조건부 사용 가능**. 아래 정밀검사 기준으로 확실한 중복만 제거한 예상 적재 행 수는 **1,739,791행**이다. 장비·월도 중복은 DV 값이 다른 경우가 많으므로 자동 제거하면 안 된다.

## 5. 주요 컬럼 품질

### 정상 또는 양호

- `Billing Period`: 세 목록 시트 모두 결측 0건, 정수 `YYYYMM` 형식이다.
- 고객 코드와 고객명: 세 목록 시트 모두 결측 0건이다.
- `Total DV`: 세 목록 시트 모두 결측 0건이며 정수형이다.
- 원본 목록 시트에는 수식 셀이 없어 저장된 값 기준으로 재현 가능하다.

### 주의

- 장비 일련번호는 숫자와 문자가 혼재한다.
  - 첫해: 숫자 760,625건, 문자 344건
  - 둘째 해: 숫자 568,766건, 문자 257건
  - 셋째 해: 숫자 475,938건, 문자 6,633건이며 그중 숫자 모양 문자열 6,523건
  - 정수 변환하지 말고 앞자리 0과 문자 접미사를 보존하는 문자열로 표준화해야 한다.
- `Total DV` 음수는 각각 154건, 284건, 106건이다. 반품·검침 정정·재청구 중 무엇인지 확인하고 삭제하지 않은 채 조정 플래그를 둔다.
- `Total DV` 0은 각각 335,329건(44.07%), 139,636건(24.54%), 105,713건(21.91%)이다. 0은 결측과 구분해 보존한다.
- 최신 파일의 완전 동일 행 28,473건은 적재 전에 중복 원인을 확인하고, 원본 행 번호와 파일 해시를 보존한 상태에서 제거 여부를 결정한다.
- `Cost Center` 결측은 첫해 13건, 둘째 해 1,122건이다. 핵심 고객·장비·DV 분석에는 직접적인 차단 요인은 아니지만 조직별 분석에는 영향을 준다.

## 6. 연도별 스키마 변화

세 기간에 공통으로 사용할 수 있는 핵심 필드는 다음과 같다.

- 월도
- 고객 코드, 고객명
- 품목/모델 코드
- 장비 일련번호와 모델+일련번호 결합 키
- 제품 계층(PL4, PL6 등)
- 계약 구분
- 흑백 DV, 흑백 A4/A3 DV
- 풀컬러 DV, 컬러 A4/A3 DV
- 총 DV
- 총 매출

주의할 변화:

- 고객·품목·장비 컬럼명이 `Customer No`/`CustomerNo`, `Customer Name`/`CustomerName`, `Part No.`/`PartNo.`, `Serial No`/`SerialNo`처럼 달라졌다.
- 첫째·둘째 파일에는 CV 및 REV 세부 컬럼이 있으나 최신 파일에는 없다.
- 둘째·셋째 파일에는 PL2가 추가되어 있다.
- 둘째 파일 끝의 잔여 3개 열은 실제 목록 데이터가 모두 비어 있어 적재 대상에서 제외한다.

권장 표준화는 원본명을 보존하는 `source_*` 컬럼과 분석용 표준 컬럼을 함께 두는 방식이다.

## 7. 출고 데이터와 결합 가능성

출고 파일에서 확인한 고객 코드/고객명과 DV의 고객 코드는 결측이 없어 1차 결합 키로 적합하다. 다만 고객 코드만으로 품목 출고와 장비 DV를 직접 1:1 결합하면 고객 내 여러 장비가 중복 결합될 수 있다.

권장 분석 단위:

1. 월도 + 고객 코드 집계: 고객 수준 출고량과 고객 총 DV 비교
2. 월도 + 고객 코드 + 장비 키: 장비별 출고 식별자가 실제로 대응할 때만 사용
3. 모델/제품 계층: 출고 품목과 장비 모델 간의 별도 매핑 테이블을 만든 뒤 집계

앱 적재 전에 확인할 키:

- 고객 코드가 기간 간 동일 고객을 안정적으로 나타내는지
- 모델+일련번호 결합 열이 장비의 영구 식별자인지
- 한 장비·월도에 여러 행이 허용되는 업무 사유
- `Total DV`가 여섯 DV 구성 컬럼의 합계인지 전 행 검증

## 8. 권장 정제 규칙

1. 파일 해시와 원본 행 번호를 적재 이력에 저장한다.
2. 컬럼명 변형을 표준명으로 매핑하되 원본 컬럼명도 보존한다.
3. 월도는 `YYYYMM` 정수에서 월 시작일 날짜로 변환하고 원본값도 유지한다.
4. 고객 코드와 장비 일련번호는 문자열로 저장한다.
5. `202403`은 둘째 파일의 값을 보존하고 첫째 파일의 44,299건을 적재 대상에서 제외한다. 원본 행은 감사 목적으로 보존한다.
6. 최신 파일의 완전 동일 초과 행 28,473건은 한 건만 남기되 파일 해시와 원본 행 번호를 보존한다.
7. 음수 DV는 삭제하지 말고 `is_adjustment` 후보 플래그를 둔다.
8. 0 DV와 결측을 구분한다.
9. 장비+월도 중복은 DV 값 충돌이 많으므로 자동 제거하지 않는다. 계약·청구·검침 구분 키를 확인해 집계 규칙을 확정한다.
10. 최신 월 완전성 상태를 `complete`, `provisional`, `unknown`으로 관리한다.
