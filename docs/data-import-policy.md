# SSDA 데이터 가져오기 정책

작성일: 2026-09-29  
상태: 원본 프로파일 근거 기반 초안 — `approvalRequired` 항목은 업무 승인 전 공식 지표에 사용하지 않음

## 1. 공통 원칙

- 원본 파일, 파일 SHA-256, 원본 시트명, 원본 행 번호와 원본 열 이름을 변경하지 않고 보존한다.
- 통화는 KRW만 허용한다. `Currency` 열이 있는 DV 파일은 값이 `KRW`가 아니면 오류로 처리한다.
- `Customer No`와 `Customer Name`이 모두 일치할 때만 고객을 자동 연결한다. 하나만 일치하거나 동일 번호에 이름이 다르면 검토 대상으로 격리한다.
- 월도는 해당 월의 1일 UTC 날짜로 표준화하되 원본 월도 값도 보존한다. 회계연도는 4월 1일 시작이며 시작연도로 표시한다.
- 원본의 0과 결측을 서로 바꾸지 않는다. 숫자는 부동소수점으로 반올림하지 않고 정확한 십진 문자열로 읽는다.
- 매핑 파일은 `config/source-mappings.json`이며, 프로파일에서 확인되지 않은 헤더를 임의로 추가하지 않는다.

## 2. 필드 결정표

## 3. 음수·0 값 정책

음수 출고수량과 음수 DV의 상태는 `review_required`다.

- 원본 부호를 유지하고 삭제, 절댓값 변환, 0 치환을 하지 않는다.
- 검증 경고 `NEGATIVE_QTY_REVIEW` 또는 이에 대응하는 DV 조정 경고를 생성한다.
- 업무 규칙 승인 전 해당 버전은 `provisional`로 표시하며 `official/final` 상태로 전환하지 않는다.
- 0 수량과 0 DV는 유효한 원본값으로 보존하고 결측과 구분한다.

## 4. 중복 및 기간 겹침 정책

- 출고 원본은 완전 동일 행 중복이 확인되지 않았으므로 업무키를 추정해 제거하지 않는다.
- DV `202403`은 후속 추출본인 두 번째 파일을 분석 대상으로 우선하되, 첫 번째 파일의 행도 원본 계보에 보존한다.
- 최신 DV 파일의 완전 동일 행은 원본 계보를 유지한 채 한 행만 분석 대상에 포함할 수 있다.
- 장비·월도 중복은 DV 값 충돌이 대부분이므로 자동 제거하거나 한 행을 선택하지 않는다.
- 실패한 검증, 미승인 버전 또는 재시도 중인 작업은 활성 버전을 변경할 수 없다.

## 5. 파일별 예외

- `Cost(24.04~25.03).xlsx`는 화면 피벗이 아니라 47개 원본 필드가 있는 피벗 캐시를 읽는다. 원본 `List` 확보 시 같은 계약으로 재검증한다.
- 최신 DV 파일에는 `Currency` 열이 없다. 업로드 메타데이터와 업무 승인으로 KRW임이 확정되기 전에는 활성화하지 않는다.
- `Service Date`의 비정상 큰 숫자는 실제 날짜로 변환하지 않고 결측 대체 흔적으로 보존한다.

## 6. 승인 전 금지 사항

- 금액 후보를 공식 비용·매출 지표로 표시하지 않는다.
- 품목을 부품 또는 소모품으로 임의 분류하지 않는다.
- 서로 다른 조직 필드를 하나의 SVC팀 이력으로 간주하지 않는다.
- 음수·0 값을 제거한 집계를 기본값으로 만들지 않는다.
- 고객번호 또는 고객명 하나만으로 자동 고객 연결을 만들지 않는다.
