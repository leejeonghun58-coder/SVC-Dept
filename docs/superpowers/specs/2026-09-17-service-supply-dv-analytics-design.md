# 서비스 자재 출고·DV 통합분석 시스템 — 설계 명세

작성일: 2026-09-17  
영문명: **Service Supply & DV Analytics**  
약칭: **SSDA**  
상태: **최종 승인 — 구현 계획 작성 허용**

## 1. 목적

부품·소모품 출고 데이터와 Document Volume(DV) 데이터를 통합해 월별 변화, 품목별 이상 변화, 고객명별 출고 효율과 데이터 품질을 조회하는 사내 웹 시스템을 구축한다.

사용자는 회사 PC의 최신 Microsoft Edge 또는 Google Chrome에서 별도 프로그램 설치 없이 이용한다. 반복적인 Excel 검색과 수작업 집계를 줄이고, 검증·승인된 데이터만 운영 분석에 사용한다.

## 2. 사용자와 운영 범위

- 사용자: 사용자 본인과 소수의 승인된 직원
- 로그인: 초대 전용 회사 이메일 계정
- MVP 권한: 승인된 사용자 모두 동일한 업무 권한
- 언어: 한글
- 화면: 데스크톱 중심, 모바일 전용 UI 제외
- 통화: KRW 단일 통화
- 회계연도: 매년 4월 1일~다음 해 3월 31일
- 회계연도 표기: 시작 연도 기준. 예: `FY24 (2024.04–2025.03)`
- 배포·저장: GitHub 비공개 저장소, Vercel, Supabase

## 3. 확인된 데이터

### 출고·비용

- `Cost(24.04~25.03).xlsx`: 271,968행

- 음수 수량 3,252행과 0수량 2,932행이 확인되었다.

### DV

- `DV(23.04~24.03).xlsx`: 760,969개 유효 레코드
- `DV(24.04~25.03).xlsx`: 569,023개 유효 레코드

상세 프로파일은 `analysis/COST_DATA_PROFILE.md`, `analysis/DV_DATA_PROFILE.md`, `analysis/dv_duplicate_analysis.json`을 기준으로 한다.

## 4. MVP 기능

### 4.1 출고 대시보드

- 로그인 후 기본 화면이다.
- 기본 기간은 적재 데이터의 최신 월을 포함한 최근 12개월이다.
- `전체 / 부품 / 소모품`을 한 화면에서 전환한다.
- 고정 필터는 기간, 구분, 품목, 고객명, SVC팀이다.
- 장비 모델·제품군, 직판·위탁 등은 접이식 상세 필터로 제공한다.
- 출고 수량, 출고 금액과 총비용을 서로 다른 지표로 표시한다.
- 출고 수량을 기본 KPI, 기본 차트 측정값과 기본 정렬 기준으로 사용한다.
- 전년 동월 대비(YoY)를 기본 비교로 사용하고 전월 대비(MoM)를 보조로 제공한다.
- 출고 수량 상위, YoY 증가 상위와 감소 상위 품목을 분리해 표시한다.
- 비교 기간이 없으면 0%가 아닌 `비교 데이터 없음`으로 표시한다.

### 4.2 품목 분석

- 대시보드의 품목 선택 시 현재 필터 맥락을 유지하고 이동한다.
- 월별 출고 수량, 출고 금액과 총비용 추이를 제공한다.
- 주요 고객명, 장비 모델과 SVC팀별 구성 및 전년 비교를 제공한다.
- 관련 출고 상세행은 커서 기반 목록으로 제공한다.

### 4.3 고객명·DV 분석

- 고객명 검색 또는 다른 화면의 고객명 선택으로 진입한다.
- 대시보드, 품목 분석과 상세표에서 고객명을 클릭하면 고객 상세 화면으로 이동한다.
- 고객 상세 화면의 대상은 `Customer No`와 `Customer Name`이 모두 일치하는 고객으로 식별한다.
- 월별 출고 수량·금액·총비용과 총 DV를 함께 제공한다.
- `1,000 DV당 출고량 = 출고 수량 / 총 DV × 1,000`으로 계산한다.
- DV가 0 또는 누락이면 `계산 불가`로 표시한다.
- 부품과 소모품 출고내역을 구분해 각각의 수량·출고 금액·총비용과 품목 상세를 제공한다.
- `전체 / 부품 / 소모품` 전환과 기간 필터를 제공한다.
- 품목 구성, YoY 변화와 고객 연결 상태를 제공한다.
- 현재 고객 상세 화면의 DV·부품·소모품 출고 결과를 고객별 보고서로 출력할 수 있게 한다.
- 고객별 보고서는 Excel과 PDF 두 형식으로 제공한다.
- Excel은 현재 필터의 상세 데이터 분석용으로, PDF는 정돈된 공유·인쇄용으로 구분한다.
- 장비 단위 출고·DV 통합분석은 MVP 이후로 연기한다.

### 4.4 데이터 관리

- 승인된 사용자는 출고 또는 DV Excel을 필요할 때 업로드할 수 있다.
- 진행률, 현재 처리 단계, 경고와 오류를 화면에 표시한다.
- 스키마, 기간, 행 수, 중복, 필수값, 이상치와 기존 버전 차이를 검사한다.
- 사용자가 검증 결과를 확인하고 승인해야 운영 데이터에 반영한다.
- 동일 기간 수정본은 신규·삭제·변경 행 수와 수량·금액·비용·DV 차이를 보여준 뒤 기간 전체를 새 버전으로 교체한다.
- 같은 파일 해시는 중복 업로드로 차단한다.
- 이전 버전을 보관하고 화면에서 복구할 수 있다.
- 복구도 새 감사 이벤트로 기록한다.

### 4.5 고객 매핑과 데이터 품질

- 출고와 DV는 `Customer No`와 `Customer Name`이 모두 일치할 때만 자동 연결한다.
- 하나라도 다르면 자동 연결하지 않고 미연결 목록에 표시한다.
- 승인된 사용자가 동일 고객임을 확인한 뒤 고객 매핑표에 등록한다.
- 승인 매핑은 과거를 포함한 전체 활성 데이터에 적용해 집계를 다시 계산한다.
- 원본 값은 변경하지 않으며 매핑 등록·수정·해제 이력을 남긴다.
- 음수 수량, 0수량, 누락 월, 중복 기간, 필수값 누락과 비정상 통화 등을 품질 이슈로 제공한다.

### 4.6 Excel 다운로드

- 일반 대시보드·품목 분석의 데이터 다운로드 형식은 Excel만 지원한다.
- 고객 상세의 정식 보고서는 4.7절에 따라 Excel과 PDF를 모두 지원한다.
- 요약 시트와 현재 필터가 적용된 상세 데이터 시트를 포함한다.
- 조회 기간, 적용 필터, 생성 시각과 데이터 버전을 명시한다.
- 수량·출고 금액·총비용의 원 단위 값을 보존한다.

### 4.7 고객별 보고서 출력

- 고객 상세 화면에서 `Customer No + Customer Name` 조합과 현재 조회 기간을 기준으로 생성한다.
- Excel과 PDF 형식을 모두 제공한다.
- Excel은 요약과 필터가 적용된 DV·부품·소모품 상세 데이터 시트를 포함한다.
- PDF는 회의, 공유와 인쇄에 적합한 요약+분석형 고정 레이아웃 보고서로 생성한다.
- 두 형식 모두 고객번호, 고객명, 조회 기간, 적용 필터, 생성 시각과 데이터 버전을 명시한다.
- PDF에는 고객 기본정보, 핵심 KPI, 월별 DV·출고 추이, 부품·소모품 구성, 주요 품목과 YoY 변화를 포함한다.
- PDF에는 모든 출고 상세행을 넣지 않으며 전체 상세는 Excel에서 제공한다.

### 4.8 고객 상세 화면과 보고서 구성

- 고객명 클릭 시 `Customer No + Customer Name` 조합을 전달해 정확한 고객 상세 화면을 연다.
- 상단에는 고객번호, 고객명, 조회 기간, 연결 상태와 데이터 버전을 표시한다.
- KPI는 총 DV, 전체 출고 수량, 부품 출고 수량, 소모품 출고 수량, 출고 금액과 총비용을 제공한다.
- 월별 DV와 월별 출고 추이는 해석이 섞이지 않도록 구분된 차트로 보여주되 같은 월 축을 사용한다.
- 부품·소모품 구성과 각 범주의 주요 품목, 수량, 금액, 비용 및 YoY를 제공한다.
- 상세표는 `전체 / 부품 / 소모품` 전환과 정렬·검색을 지원한다.
- Excel 보고서는 `요약`, `월별 DV`, `부품 출고 상세`, `소모품 출고 상세` 시트를 기본으로 한다.
- PDF 보고서는 고객 요약, DV·출고 월별 분석, 부품·소모품 구성과 주요 품목을 읽기 쉬운 여러 페이지로 구성한다.
- PDF는 현재 필터를 반영하되 모든 상세행 대신 주요 순위와 요약을 포함한다.

## 5. MVP 제외 범위

- 수요 예측과 예측 정확도 비교
- 장비 단위 출고·DV 통합분석
- 이메일·메신저·푸시 알림
- 공개 회원가입과 역할별 세분 권한
- 모바일 전용 화면
- CSV 다운로드
- 환율 변환과 다중 통화 합산
- 이익·마진·이익률 파생지표

수요 예측은 데이터 품질과 집계 정확도가 확인된 뒤 2단계에서 기준선·백테스트와 함께 설계한다.

## 6. 시스템 구조

1. GitHub 비공개 저장소가 소스와 배포 이력의 기준이다.
2. Next.js 웹 앱을 Vercel에 배포한다.
3. Supabase Auth가 초대 전용 로그인을 담당한다.
4. Supabase Postgres가 운영 데이터, 사전 집계, 매핑, 버전과 감사 이력을 저장한다.
5. 원본 Excel은 Supabase 비공개 Storage의 버전별 고유 경로에 보관한다.
6. 브라우저는 6MB 초과 파일을 TUS 방식으로 Storage에 직접 재개 가능 업로드한다.
7. Vercel Workflow가 파일 검증, 표준화, 임시 적재와 사전 집계를 비동기로 처리한다.
8. 사용자가 승인하면 짧은 데이터베이스 트랜잭션으로 활성 버전 포인터를 교체한다.
9. 처리 실패 또는 승인 취소는 기존 활성 데이터에 영향을 주지 않는다.

Vercel 함수 요청 본문을 대용량 파일 전송 경로로 사용하지 않는다. 구현 착수 시 Vercel 요금제의 Workflow 제공 범위, 실행 자원, 기간과 비용을 최신 공식 문서로 다시 확인한다.

## 7. 데이터 구조

### 핵심 영역

- `upload_jobs`: 업로드와 처리 상태
- `data_versions`: 기간, 해시, 검증 결과와 활성 상태
- `shipment_records`: 버전별 출고 표준화 행
- `dv_records`: 버전별 DV 표준화 행
- `customers`: 고객 기준정보
- `customer_mappings`: 승인된 고객 연결 규칙
- `items`: 품목과 부품·소모품 구분
- `validation_issues`: 오류와 경고
- `monthly_item_summary`: 품목 월별 집계
- `monthly_customer_summary`: 고객명 월별 집계
- `monthly_customer_item_summary`: 고객명·품목 월별 집계
- `audit_events`: 중요 변경 이력

### 저장·조회 원칙

- 모든 상세행과 집계는 데이터 버전 키를 가진다.
- 원본 행과 원본 파일은 덮어쓰지 않는다.
- 금액과 비용은 정확한 `numeric` 계열로 저장한다.
- 월도는 날짜 형식으로 저장하고 FY 표기는 조회 계층에서 계산한다.
- 대량 적재는 배치 또는 `COPY` 방식을 사용한다.
- 외래키, RLS 조건과 실제 필터 조합에 필요한 인덱스를 둔다.
- 상세 목록은 큰 OFFSET 대신 커서 기반 페이지 이동을 사용한다.
- 약 230만 행 규모에서는 처음부터 월별 파티션을 도입하지 않고 측정 결과에 따라 판단한다.

## 8. 처리 흐름

```text
Excel 직접 업로드
  → 해시·파일·시트·열 검사
  → 새 버전의 표준 스키마로 적재
  → 중복·누락·이상치·미연결 검사
  → 이전 활성 버전과 차이 계산
  → 조회용 사전 집계 생성
  → 사용자 검토·승인
  → 활성 버전 전환
```

- 오류는 승인 불가 상태다.
- 경고는 사용자가 내용을 확인한 뒤 승인할 수 있다.
- Workflow 재시도는 중복 실행에도 결과가 변하지 않도록 단계별로 설계한다.
- 집계가 완성되기 전에 활성 버전을 전환하지 않는다.

## 9. 화면 구조

### 전역 메뉴

1. 출고 대시보드
2. 품목 분석
3. 고객명·DV 분석
4. 데이터 관리
5. 매핑·품질

### 대시보드 배치

```text
┌──────────────┬─────────────────────────────────┐
│ 기간         │ 출고수량 │ 출고금액 │ 총비용 │ YoY │
│ 구분         ├─────────────────────────────────┤
│ 품목         │          월별 추이               │
│ 고객명       ├─────────────────────────────────┤
│ SVC팀        │ 수량 상위 │ 증가 상위 │ 감소 상위 │
│              ├─────────────────────────────────┤
│ 상세 필터 ▼  │          품목 상세표             │
└──────────────┴─────────────────────────────────┘
```

- 왼쪽 고정 필터와 오른쪽 분석 영역을 사용한다.
- 오른쪽은 KPI → 월별 추이 → 순위 → 상세표 순서다.
- 균형형 정보 밀도와 틸·그린 계열의 차분한 사내 시스템 스타일을 사용한다.
- 증가, 감소, 오류는 색상 외에도 아이콘과 텍스트로 구분한다.
- 좁은 데스크톱 창에서는 필터를 접고 표 내부에 가로 스크롤을 제공한다.
- 모든 화면에 기간, 필터, 데이터 버전과 최신 적재 시각을 확인할 수 있게 한다.

표시 용어는 반드시 `SVC팀`과 `고객명`을 사용한다. `담당 조직` 또는 단독 `고객`이라는 UI 표현은 사용하지 않는다.

## 10. 지표 규칙

- 출고 수량: 승인된 활성 출고 행의 수량 합계
- 출고 금액: 원본에서 확정될 출고 금액 필드의 합계
- 총비용: 원본에서 확정될 총비용 필드의 합계
- YoY: 현재 월과 정확히 12개월 전 동월 비교
- MoM: 직전 월 비교
- 1,000 DV당 출고량: 출고 수량 / 총 DV × 1,000
- 0수량 행: 수량 합계에는 0, 금액·비용은 원본값이 있으면 포함하고 품질 건수로 별도 표시
- DV 0·누락: 비율을 계산하지 않고 `계산 불가`
- 비교 기준 없음: 증감률을 0으로 만들지 않고 `비교 데이터 없음`
- 출고 금액과 총비용은 별도 지표이며 그 차이를 이익으로 해석하지 않는다.

## 11. 보안

- 공개 회원가입을 비활성화한다.
- 앱 사용자 명부에 등록된 인증 사용자만 업무 데이터에 접근한다.
- 외부 노출 테이블에 RLS를 적용하고 RLS 조건 열을 인덱싱한다.
- `service_role` 등 관리자 비밀키를 클라이언트에 노출하지 않는다.
- Storage는 비공개 버킷과 최소 권한 정책을 사용한다.
- 보안상 민감한 원본 파일과 상세 내보내기는 Git에 커밋하지 않는다.
- `.env`, 키와 토큰은 Vercel·Supabase의 비밀 설정으로 관리한다.
- 권한 변경, 업로드, 승인, 복구와 고객 매핑 변경은 감사 이력을 남긴다.

## 12. 오류 처리

- 네트워크 중단 시 파일 업로드를 재개한다.
- 필수 열 누락, 지원하지 않는 파일·시트, 해석 불가능한 데이터는 운영 반영 전에 실패 처리한다.
- 오류 메시지는 실패 단계, 원인과 사용자가 취할 수 있는 조치를 포함한다.
- 재시도 가능한 오류와 사용자 수정이 필요한 오류를 구분한다.
- 반복 실패해도 활성 데이터는 유지한다.
- 빈 결과, 0, 결측, 계산 불가와 로딩 실패 상태를 서로 구분한다.
